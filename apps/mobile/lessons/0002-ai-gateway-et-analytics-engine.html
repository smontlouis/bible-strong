Observer sans lire les recherches

AI Gateway surveille Qwen. Analytics Engine mesure toute la chaîne. En mode metadata-only, aucun des deux ne conserve ce que l'utilisateur a écrit.

Le trajet d'une recherche

1. Resource WorkerVérifie App Check et cherche la réponse dans le cache 24 h.
2. AI GatewaySur un cache miss, mesure l'appel à Qwen sans stocker la requête.
3. Qwen + PostgreSQLQwen encode le sens ; PostgreSQL retrouve et classe les passages.
4. Analytics EngineReçoit uniquement des chiffres et catégories sur le trajet complet.

AI Gateway : le compteur devant Qwen

Aujourd'hui, le Worker appelle directement Qwen avec env.AI.run(). Avec une Gateway, il fait le même appel en ajoutant une configuration gateway. Le texte traverse toujours Cloudflare pour être transformé en embedding, mais la Gateway ne doit pas le conserver dans ses logs.

Elle peut enregistrer : modèle utilisé, durée, nombre de tokens, coût estimé, succès, erreur ou timeout. Elle peut aussi imposer un plafond de dépense. Elle ne voit pas le classement PostgreSQL et ne sait pas si les résultats finaux sont bons.

Metadata-only : conserver « Qwen · 38 ms · 9 tokens · succès », jamais « l'utilisateur a recherché anxiété ». Les logs AI Gateway contenant les payloads sont activés par défaut ; leur désactivation est donc une condition de sécurité.

Analytics Engine : notre tableau de bord de recherche

Le Worker écrit lui-même un petit datapoint technique pour décrire le trajet complet. Par exemple :

langue=fr · cache=MISS · chemin=semantic
total=180 ms · qwen=38 ms · sql=112 ms · résultats=20

On peut ensuite calculer les p50/p95, les taux d'échec et la proportion de recherches qui atteignent réellement Qwen. Ce sont des tendances agrégées, pas un journal permettant de retrouver une recherche individuelle.

Exemple : « anxiété »

Situation AI Gateway Analytics Engine
Premier appel, cache MISS Mesure Qwen : tokens, durée, coût, statut. Mesure cache + Qwen + SQL + résultats.
Deuxième appel, cache HIT Aucun événement : Qwen n'est pas appelé. Enregistre un HIT rapide, sans SQL ni Qwen.
Recherche lente Indique si Qwen est lent. Indique si le temps vient du cache, de Qwen ou de PostgreSQL.

Ce que nous ne stockons pas

  • pas de texte de recherche ;
  • pas de hash de la recherche ;
  • pas d'UID Firebase ni d'identifiant stable de l'appareil ;
  • pas de résultats ou de préoccupations spirituelles individuelles.

Ce que ces outils ne font pas

Ils n'améliorent pas directement la pertinence, ne remplacent ni pgvector ni PostgreSQL, ne changent pas l'interface et ne remplacent pas App Check. Ils donnent les mesures nécessaires pour décider ensuite si un reranker, Smart Placement ou Vectorize apporte réellement quelque chose.

Vérification rapide

Une recherche est lente mais Qwen répond en 25 ms. Quel outil permet de découvrir que PostgreSQL prend 400 ms ?

Afficher la réponse

Analytics Engine, car il mesure le pipeline complet. AI Gateway sait seulement que l'appel à Qwen a pris 25 ms.
